# Handle Proofs

Bind GitHub accounts and web domains to GenLayer addresses, verified by validator consensus and written in Rust. A registry other contracts can ask: "does `github:alice` belong to this address?", "which domains has this address proven?". Bindings stay honest over time: anyone can trigger a recheck, and a binding whose proof was taken down is dropped.

- **Contract (Bradbury testnet):** `0x3bfa7dac02d3b271162150fd2d365dfb7a4b2885` ([explorer](https://scan.bradbury.genlayer.com/address/0x3bfa7dac02d3b271162150fd2d365dfb7a4b2885))
- **Language:** Rust, `genlayer_sdk` (genvm-executor `v0.3-dev` @ `6ec6c39`), deployed with [genlayer-chunked-deploy](https://github.com/brossXnft/genlayer-chunked-deploy)

## The problem

On-chain apps keep needing to know who is behind an address: pay a GitHub contributor, show a verified project domain, gate a grant to a real maintainer, stop impersonation. Today that means a centralized attestation service, a signed message checked by someone's backend, or trusting whatever the user typed. A GenLayer contract can check the proof directly on the public web, and several validators must see the same thing before it counts.

## How it works

The owner publishes one token line, generated by the contract's `statement` view:

```
genlayer-handle-proof:v1:<chain>:<registry>:<kind>:<handle>:<address>
```

It names the chain and this registry (so a proof cannot be replayed on another registry), the handle and the address. Where it goes:

| Kind | Proof method | Where the token goes |
|---|---|---|
| `github` | gist | Any file of a **public gist owned by that login**. Claim with the gist id or URL. |
| `domain` | `dns` | A TXT record at `_genlayer-proof.<domain>`. Read through two DNS-over-HTTPS resolvers (Google, Cloudflare). |
| `domain` | `well-known` | A line in `https://<domain>/.well-known/genlayer-proof.txt`. |

`claim(kind, handle, proof)` runs a nondeterministic block. The leader and each validator fetch the proof themselves:

- **github:** `GET api.github.com/gists/<id>`. The gist owner's login must equal the handle (case-insensitive), and one line of one file must equal the token exactly.
- **dns:** a TXT string must equal the token (quoted strings joined as DNS does).
- **well-known:** one line of the file must equal the token.

Validators compare only the verdict (`found`). The human-readable detail may differ, for example which resolver answered. A leader that claims "found" when the proof is not there is outvoted. The binding is stored only after agreement and records the address, method, proof reference and timestamps.

The rest of the design:

- **A valid fresh proof wins.** If `github:alice` was bound to address A and alice publishes a proof for B, B's claim moves the handle (logged as `rebound`). Control of the account is what counts, so account recovery or wallet rotation just works.
- **Recheck by anyone.** `recheck(kind, handle)` re-verifies the stored proof. Still there: `checked_at` is refreshed. Gone: the binding is removed (`dropped`). A deleted gist or DNS record therefore does not leave a stale claim behind.
- **Revoke by the owner.** `revoke(kind, handle)` from the bound address.
- **Bounded state.** At most 16 handles per address. Handles are normalized: lowercase, GitHub login rules, valid DNS labels, no bare IPs.

## Using it from another contract

```python
reg = gl.contract.get_at(HANDLE_PROOFS)
if not reg.view().is_bound("github", "alice", gl.message.sender_address):
    raise gl.vm.UserError("prove your GitHub account first")
```

| Method | Kind | Returns |
|---|---|---|
| `statement(kind, handle, address)` | view | `{token, how}`: the exact line to publish |
| `claim(kind, handle, proof)` | write, nondet | the stored binding (+ `previous_owner` if it moved) |
| `recheck(kind, handle)` | write, nondet | `{status: "valid" | "dropped", …}` |
| `revoke(kind, handle)` | write | `{status: "revoked"}` |
| `resolve(kind, handle)` | view | binding or `null` |
| `is_bound(kind, handle, address)` | view | `bool` |
| `handles_of(address)` | view | list of bindings |
| `recent(n)` / `stats()` | view | event log (`bound`, `rebound`, `rechecked`, `dropped`, `revoked`) and counts |

## Build and deploy

```bash
cargo build --release --target wasm32-wasip1
wasm-opt -Oz --enable-bulk-memory --enable-sign-ext --enable-mutable-globals \
  --enable-nontrapping-float-to-int target/wasm32-wasip1/release/handle-proofs.wasm -o handle-proofs.wasm
python tools/wasm_strip.py handle-proofs.wasm handle-proofs.wasm --version v0.3.0
python tools/chunked_deploy.py handle-proofs.wasm --test-method version --send
```

## Limits

- GitHub's unauthenticated API allows 60 requests per hour per IP. Each validator fetches from its own IP, so this only matters under heavy use from one node.
- DNS answers can lag after a record changes. If validators disagree, the claim does not reach consensus; retry after the TTL.
